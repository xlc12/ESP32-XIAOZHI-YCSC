# CI130X 故障对照

## 现象 → 原因 → 处理

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 完全没有声音，日志反复出现等待就绪 | 同步逻辑依赖「收到过一次就绪」，而 CI 早于 ESP32 启动，消息已错过 | 去掉就绪门槛，改为后台任务周期收敛 |
| 能听到提示音，但说话不识别 | 上行 PCM 为静音：CI 的录音门控未打开 | 确认 `0x011A` 已下发且成功；看上行日志的字节数与 rms |
| 每次都短读 1920/2048 字节 | DMA 描述符大小不能整除读长度 | 让 `dma_frame_num × slot字节 × 声道` 能整除单次读字节数（16k/16bit/双声道取 256） |
| `Ringbuffer of AFE(FEED) is full` 刷屏 | `Read()` 无数据时立即返回，输入任务空转 | 在 `Read()` 尾部按采样率补齐时间 |
| 唤醒后云端没反应 | ESP32 本地唤醒模型没收到有效音频 | 改用 CI 的 `WAKE_UP` 事件桥接 `WakeWordInvoke` |
| 时好时坏，怎么喊都不识别 | ① 音频任务被串口应答阻塞；② 重复唤醒掐断会话；③ CI 中途重启 | ① 串口改异步；② 唤醒回调按状态过滤；③ 收到就绪事件强制整组重发 |
| 日志显示满字节但 rms 恒为 0 | CI 在输出 zero buffer（门控关闭），不是没数据 | 看门狗把全静音也计入断流，并重发 `0x011A` |
| rms 打印成 2147483647 | 平方和用 int32 溢出 | 改用 int64 累计 |
| 播放瞬间整机复位（Brownout） | 功放启动电流冲击 | 换大电流电源、功放电源脚加 470~1000 µF + 0.1 µF、降低音量档 |
| 空闲时底噪大、耗电高 | 功放常开 | 用 GPIO 控制功放使能，跟随 `output_enabled_` |
| CI 在上电后反复上报就绪 | 供电跌落 / 看门狗 / 高速串口干扰 | 查电源与地、缩短 UART 走线、必要时降波特率 |

## 日志判读

```
[AUDIO-IN ] 2048/2048 B 512 frm rms=1431  peak=2540  silent=0  OK
              ↑收到字节 ↑期望  ↑帧数  ↑能量   ↑峰值   ↑连续静音计数
```

- `received < wanted` 偶发：CI 送数抖动，可忽略。
- `received == 0` 或 `rms == 0` 持续：断流。
- `silent` 持续递增到阈值：看门狗触发，随后应看到重发开始录音的命令日志。
- `2048/2048` 且 `rms` 跟随说话变化：链路正常，问题在云端或会话状态。

## 会话链路检查顺序

1. 有没有 `WAKE_UP` 事件；
2. 有没有从 idle 进入 connecting/listening；
3. 上行 rms 是否随说话变化；
4. 有没有 `PCM_FINISH`；
5. 有没有下行数据与播放窗口开启日志；
6. 功放使能日志是否变为 ON。
